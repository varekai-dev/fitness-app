# fitness-app

Особистий фітнес-трекер на React Native (Expo). Усі дані зберігаються локально на пристрої.

- **Тренування** — плеєр: підходи вводяться колесами, як у годиннику iOS, таймер відпочинку з кільцем, пауза / завершення утриманням.
- **Програми** — дні, що йдуть по колу, з цілями: підходи, діапазон повторень, час / дистанція, відпочинок.
- **Вправи** — бібліотека з групами м'язів, фото та відео техніки на YouTube.
- **Прогрес** — історія, «минулого разу», графік по вправі (e1RM для силових), особисті рекорди, календар активності.
- **Вага тіла і калорії** — щоденна вага з графіком і згладженим трендом (без денної «пилки»), темп за тиждень і прогноз дати досягнення цільової ваги, орієнтовні спалені калорії за тренування й тиждень.
- **Фото прогресу** — фото спереду, збоку й ззаду зберігаються лише на пристрої; порівняння «до / після» слайдером, з вагою на кожну дату, і нагадування раз на тиждень.
- **Харчування** — страви вводяться текстом або фотографуються (AI розпізнає їжу й оцінює порції), калорії й БЖВ рахує AI (Groq, свій ключ у налаштуваннях); уже знайдені страви беруться з локальної бази. Прийом їжі можна повторити в один тап («Як учора») або зберегти як шаблон. AI коментує день: чого бракує до цілі (білок рахується від ваги й мети) і 3 варіанти перекусу, які додаються в один тап. Рекомендована калорійність за профілем (зріст, вік, вага, активність).
- **Вода** — денна норма, швидке додавання склянок, графік за тиждень.
- **Віджети на робочому столі Android** — «Сьогодні» (вода, калорії й наступне тренування разом) або кожне окремо; тап відкриває потрібний екран, опівночі вода й калорії обнуляються. Дані оновлює застосунок, тож віджети є лише в APK, не в Expo Go.
- **Apple Health / Health Connect** — підключення в налаштуваннях інтеграцій: вага підтягується в журнал ваги, прогулянки, біг та інші тренування з годинника — в історію, а кроки й сон — у віджети «Кроки» і «Сон» на головній (лише в dev build, не в Expo Go).
- **Підсумки** — у налаштуваннях: місяць чи рік у цифрах для кожного ввімкненого розділу. Тренування (кількість, тоннаж, час, улюблена вправа, нові рекорди), харчування (середні калорії й білок, дні в межах цілі, найчастіша страва), вода (випито, середнє, дні з нормою). Картку можна поділитися картинкою.
- **Резервна копія** — у налаштуваннях: експорт усіх даних разом із фото прогресу в один файл, який зберігається через системне меню «Поділитися» в Google Drive, Telegram тощо, і відновлення з такого файлу на цьому чи новому телефоні. Ключ Groq у копію не потрапляє.

## Стек

Expo SDK 57 · Expo Router · TypeScript · expo-sqlite + Drizzle ORM

## Запуск

```bash
npm install
npx expo start          # Expo Go
npx expo run:ios        # dev build (потрібен Xcode 26.4+)
npm run android         # Expo Go на емуляторі Pixel
npm run android:build   # dev build на емуляторі Pixel
```

## Релізи

Кожен пуш у `main` запускає [release.yml](.github/workflows/release.yml). Якщо нативна частина не змінилась (той самий fingerprint, що й в одного з релізів), JS публікується як OTA-оновлення через EAS Update. Інакше GitHub Actions збирає підписаний APK (без EAS Build) і публікує його як реліз у [fitness-app-releases](https://github.com/varekai-dev/fitness-app-releases). У налаштуваннях застосунок пропонує або встановити OTA-оновлення, або завантажити новий APK.

Локально (потрібні JDK 17+ і Android SDK):

```bash
npm run build:android   # → dist/fitness-<version>.apk
```

Ключ підпису береться з `credentials.json` у корені (як його завантажує `eas credentials -p android`) або зі змінних `ANDROID_KEYSTORE_PATH`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. У CI це секрети репозиторію з тими ж назвами, але сам keystore передається в base64 як `ANDROID_KEYSTORE_BASE64`. Плюс `RELEASES_TOKEN` для публікації в репозиторій релізів і `EXPO_TOKEN` для OTA-оновлень.

## Міграції БД

Після зміни `src/db/schema.ts`:

```bash
npx drizzle-kit generate
```

Міграції застосовуються автоматично при запуску застосунку.

## Резервна копія

Файл копії — це SQLite-база, знята через online backup API SQLite з відкритого з'єднання ([src/lib/backup.ts](src/lib/backup.ts)). Обрано копію бази, а не JSON: вона переносить таблицю `__drizzle_migrations` і `user_version`, тож копія зі старішої версії після відновлення доходить до поточної схеми звичайними міграціями й content seeds при запуску, без окремого коду перетворення. Додатково у файлі є таблиця `backup_info` (позначка формату, дата, версія) і `backup_files` з фото прогресу як BLOB; при відновленні фото записуються на диск, а ці таблиці видаляються. Відновлення переписує відкриту базу тим самим backup API в одній транзакції, після чого застосунок перезапускається. Копію з новішої версії застосунку (з невідомими міграціями) імпорт відхиляє.
